架构说明

当前问题

你的服务器 www.resil-hub.cn 上 Nginx 把所有 /api/* 请求都返回了 index.html（HTML），管理后台因此报 "非JSON内容" 错误。

解决方案

把数据库放到 Cloudflare D1（免费、全球部署的 SQLite），用 Cloudflare Worker 提供 API。管理后台直接请求 Worker URL，完全绕过 Nginx。

浏览器 (admin.html) │ │ 直接请求（不经过 Nginx） ▼ Cloudflare Worker ←─── 你即将部署的 API 服务 (haihe-api.xxx.workers.dev) │ ▼ Cloudflare D1 数据库 ←─── 3 张表，存储全部教学数据 (simulation_rounds / player_decisions / chat_logs)
Cloudflare D1 免费额度：每天 500万次读 + 10万次写，对教学平台绰绰有余。
1

在你的电脑上安装 Wrangler 工具

Wrangler 是 Cloudflare 官方 CLI，用于管理 D1 和 Worker。

先确认 Node.js 已安装

在终端中执行
node -v

如果输出 v18.x.x 或更高版本，继续下一步。
如果提示找不到命令，先去 nodejs.org 下载安装 LTS 版本。

安装 Wrangler

复制粘贴执行
npm install -g wrangler

验证安装

wrangler --version

应输出类似 wrangler 3.x.x。

2

登录 Cloudflare 账号

复制粘贴执行
wrangler login

执行后会自动打开浏览器，跳转到 Cloudflare 登录页面。

  1. 如果没有账号，点击 "Sign Up" 免费注册
  2. 登录后页面会提示 "Wrangler is now authorized"
  3. 回到终端，看到 Successfully logged in. 即可
如果你在服务器上操作（无浏览器），用 wrangler login --browser=false，它会给你一个链接，复制到本地浏览器中打开完成授权。
3

创建 D1 数据库

复制粘贴执行
wrangler d1 create haihe-flood-db

执行成功后，终端会输出类似以下内容：

✅ Successfully created DB 'haihe-flood-db' in region APAC
Created your new D1 database.

[[d1_databases]]
binding = "DB"
database_name = "haihe-flood-db"
database_id = "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
关键操作：把上面输出的 database_id 值（那串带横线的字符）复制下来，后面要用。每个人的 ID 都不同。
4

建表（导入 schema.sql）

先进入项目文件夹（haihe-worker 目录），确认 schema.sql 文件存在：

复制粘贴执行
cd haihe-worker
ls schema.sql

然后执行建表：

复制粘贴执行
wrangler d1 execute haihe-flood-db --remote --file=schema.sql
--remote 参数很重要！不加的话只会在本地创建，不会部署到 Cloudflare 云端。

验证表是否创建成功：

复制粘贴执行
wrangler d1 execute haihe-flood-db --remote --command="SELECT name FROM sqlite_master WHERE type='table'"

应输出 3 张表名：

┌────────────────────┐
│ name               │
├────────────────────┤
│ simulation_rounds  │
│ player_decisions   │
│ chat_logs          │
└────────────────────┘
看到 3 张表名，说明数据库建表成功。
5

配置 wrangler.toml（填入 database_id）

用任意文本编辑器打开 haihe-worker/wrangler.toml：

wrangler.toml 文件内容
name = "haihe-api"
main = "src/worker.js"
compatibility_date = "2024-01-01"

[[d1_databases]]
binding = "DB"
database_name = "haihe-flood-db"
database_id = "把步骤3复制的ID粘贴到这里"

[vars]
ALLOWED_ORIGIN = "https://www.resil-hub.cn"

只需改一个地方：把 database_id 的值替换为步骤 3 中复制的那串 ID。

例如：

database_id = "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
6

部署 Worker（API 上线）

确保当前在 haihe-worker 目录下：

复制粘贴执行
wrangler deploy

执行成功后输出类似：

Total Upload: 6.21 KiB / gzip: 2.34 KiB
Your worker has access to the following bindings:
- D1 Databases:
  - DB: haihe-flood-db
Uploaded haihe-api (1.82 sec)
Deployed haihe-api triggers (0.23 sec)
  https://haihe-api.你的账号名.workers.dev
关键操作：记下最后一行的 URL（https://haihe-api.xxx.workers.dev），这就是你的 API 地址。
7

验证部署

7a. 健康检查

在浏览器中直接打开（或用 curl）：

把 xxx 替换为你的账号名
https://haihe-api.xxx.workers.dev/api/health

期望返回：

{"ok":true,"version":"1.0","db":"cloudflare-d1"}
看到这个 JSON 说明 Worker + D1 都正常运行。

7b. 写入测试

在终端中执行（替换 xxx）
curl -X POST https://haihe-api.xxx.workers.dev/api/data/rounds \
  -H "Content-Type: application/json" \
  -d '{"room_id":"TEST001","round_num":1,"rainfall_A":38,"rainfall_B":36,"rainfall_C":23}'

期望返回：{"ok":true}

7c. 读取测试

在终端中执行（替换 xxx）
curl https://haihe-api.xxx.workers.dev/api/data/rounds

期望返回包含刚写入数据的 JSON 数组。

7d. 清理测试数据

复制粘贴执行
wrangler d1 execute haihe-flood-db --remote --command="DELETE FROM simulation_rounds WHERE room_id='TEST001'"
8

将 admin.html 连接到 Worker

打开 http://www.resil-hub.cn/admin.html，在页面顶部找到 "服务器地址" 输入框。

填入你的 Worker URL：

https://haihe-api.xxx.workers.dev

然后点击 "应用" 按钮。

如果右侧显示 v1.0 已连接，说明管理后台已成功连接到 Cloudflare D1 数据库，"加载失败" 问题彻底解决。
每次打开 admin.html 都需要重新填入地址。如果想永久生效，可以修改 admin.html 中第 78 行的 let API = '' 为 let API = 'https://haihe-api.xxx.workers.dev'。
9

配置 Nginx 转发（可选，推荐）

如果你希望 admin.html 不需要手动填 Worker URL，可以让 Nginx 自动转发 /api/ 到 Worker：

SSH 登录到你的服务器，编辑 Nginx 配置文件：

在服务器上执行
sudo nano /etc/nginx/conf.d/haihe.conf

在 server { } 块内加入以下内容（放在其他 location 前面）：

添加到 Nginx 配置中（替换 xxx）
# API 请求转发到 Cloudflare Worker
location /api/ {
    proxy_pass https://haihe-api.xxx.workers.dev;
    proxy_ssl_server_name on;
    proxy_set_header Host haihe-api.xxx.workers.dev;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_http_version 1.1;
}

保存后验证并重载：

在服务器上执行
sudo nginx -t && sudo systemctl reload nginx
配置后，http://www.resil-hub.cn/api/health 将返回 JSON 而不是 HTML，admin.html 中 "服务器地址" 留空即可正常工作。

常见问题排查

问题现象 原因与解决
wrangler: command not found Node.js 未安装或 npm 全局路径不在 PATH 中。执行 npm install -g wrangler 后重开终端。
D1_ERROR: no such table: simulation_rounds 建表时忘了加 --remote。重新执行步骤 4 的命令。
Worker 部署后返回 500 Internal Error 查看日志：wrangler tail（实时查看 Worker 日志）。通常是 database_id 写错了。
admin.html 填入 Worker URL 后仍报错 检查浏览器控制台(F12)的具体错误。如果是 CORS 错误，确认 Worker 代码中的 cors headers 正确。
Nginx 配置后 /api/ 返回 502 proxy_ssl_server_name on; 是否遗漏。Nginx 代理 HTTPS 后端时必须加这一行。
想查看数据库中有哪些数据 wrangler d1 execute haihe-flood-db --remote --command="SELECT count(*) FROM simulation_rounds"
想清空所有数据重新开始 wrangler d1 execute haihe-flood-db --remote --command="DELETE FROM simulation_rounds; DELETE FROM player_decisions; DELETE FROM chat_logs"
想修改 Worker 代码后重新部署 编辑 src/worker.js 后重新执行 wrangler deploy
